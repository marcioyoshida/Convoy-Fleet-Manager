## Reading order

1. The three definitions and principles in the root `README.md`, then the layered chart in `architecture.md`.
2. `pipeline-compiler.md` §0 (what changed from the research) and §3 (the annotation database).
3. `debate-review.md` summary matrix and the cross-cutting decisions at the end.
4. The ADRs, which are the same decisions in a form that can be reversed one at a time.
5. `walkthroughs.md` to see the design carry nine real workloads, and where it had to be amended.
6. `user-stories/README.md` for the findings register and the structural misroutes, then one story per persona you care about.
7. `posix-command-map.md` when you need to know what a specific command does on Convoy.

## Open design work

The three abstractions that change the architecture are now drafted. Session placement and durability is drafted in [ADR 0020](adr/0020-a-session-is-a-journal-not-a-pod.md): the session is a journal and a login with a shell per terminal, the controller writes every receipt so losing the pod loses only local commands in flight, and there is no context object, since `mount` adds a cluster and `cd` switches. Networking is drafted in [ADR 0019](adr/0019-a-unit-has-an-address-reach-is-a-grant.md): only a unit has an address, the owner grants reach and the caller declares it, and the platform owns the boundary. Identity and ownership is drafted in [ADR 0016](adr/0016-identity-is-a-user-rights-belong-to-groups.md): the user is the actor, rights and ownership belong to groups. The approvals object behind `approve` is drafted in [ADR 0017](adr/0017-approvals-are-objects-on-the-process.md): an object on the process that approves a pinned plan from another person's session. The label convention that signals the platform is drafted in [ADR 0018](adr/0018-labels-are-the-signal-admission-is-the-decision.md): labels signal, admission decides. The mount namespace and fileserver design that supersedes the disk-operations research note is also pending; it will be written against [ADR 0011](adr/0011-device-tree-and-mount-table.md), which settles how clusters and other cloud resources appear as devices under `/dev` and are mounted by the session, and [ADR 0012](adr/0012-logs-and-queues-are-devices.md), which drafts logs and queues (Kafka, Redpanda, NATS, SQS) as the `/dev/queue` class with bounded reads as files, follows as streams and writes as side effects. See `stories.md` for the full list, and `user-stories/README.md` for the one hundred and fifty-eight findings and fifteen structural misroutes the persona probes raised; the forty that amend ADRs and the eighty-nine rules were applied on 2026-11-09 and 2026-11-10 (US-22's eight are proposed) to the ADRs, the command map, the compiler and the roadmap, and the five open design items are all drafted (the last two, queue schemas and artifact scrub, as ADR 0012 decision 10 and ADR 0007 amendment 5). [ADR 0013](adr/0013-native-verbs-have-one-shape.md) drafts the native verbs (`explain`, `run`, `batch`, `wait`, `replay`, the unit, device and platform verbs) as a closed set with one seven-field shape, so the stories have a text to be checked against, [ADR 0015](adr/0015-tables-and-catalogs-are-devices.md) drafts tables and catalogs (Iceberg, Delta, Hudi, warehouses) as the `/dev/table` class, where a read pins a snapshot and a write is one commit, and [ADR 0014](adr/0014-assisted-completion-the-model-proposes.md) drafts assisted completion: type-directed from the grammar first, a model only ranking and translating, and the model itself a device. [ADR 0021](adr/0021-a-node-is-tested-before-it-is-trusted.md) drafts node health without a person present: probes test each component, a policy acts on clear faults, a health agent judges the ambiguous ones within a fixed set of actions and a disruption budget, and a GPU or a shared-filesystem client is excluded before its node.
