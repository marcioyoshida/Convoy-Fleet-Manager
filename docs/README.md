## Reading order

1. The three definitions and principles in the root `README.md`, then the layered chart in `architecture.md`.
2. `pipeline-compiler.md` §0 (what changed from the research) and §3 (the annotation database).
3. `debate-review.md` summary matrix and the cross-cutting decisions at the end.
4. The ADRs, which are the same decisions in a form that can be reversed one at a time.
5. `walkthroughs.md` to see the design carry nine real workloads, and where it had to be amended.
6. `user-stories/README.md` for the findings register and the structural misroutes, then one story per persona you care about.
7. `posix-command-map.md` when you need to know what a specific command does on Convoy.

## Open design work

The three abstractions that change the architecture are now drafted. Session placement and durability is drafted in [ADR 0020](adr/0020-a-session-is-a-journal-not-a-pod.md): the session is a journal and a login with a shell per terminal, the controller writes every receipt so losing the pod loses only local commands in flight, and there is no context object, since `mount` adds a cluster and `cd` switches. Networking is drafted in [ADR 0019](adr/0019-a-unit-has-an-address-reach-is-a-grant.md): only a unit has an address, the owner grants reach and the caller declares it, and the platform owns the boundary. Identity and ownership is drafted in [ADR 0016](adr/0016-identity-is-a-user-rights-belong-to-groups.md): the user is the actor, rights and ownership belong to groups. The approvals object behind `approve` is drafted in [ADR 0017](adr/0017-approvals-are-objects-on-the-process.md): an object on the process that approves a pinned plan from another person's session. The label convention that signals the platform is drafted in [ADR 0018](adr/0018-labels-are-the-signal-admission-is-the-decision.md): labels signal, admission decides. The mount namespace and fileserver design that supersedes the disk-operations research note is also pending; it will be written against [ADR 0011](adr/0011-device-tree-and-mount-table.md), which settles how clusters and other cloud resources appear as devices under `/dev` and are mounted by the session, and [ADR 0012](adr/0012-logs-and-queues-are-devices.md), which drafts logs and queues (Kafka, Redpanda, NATS, SQS) as the `/dev/queue` class with bounded reads as files, follows as streams and writes as side effects. See `stories.md` for the full list, and `user-stories/README.md` for the one hundred and eighty-one findings and fifteen structural misroutes the persona probes raised; the forty-six that amend ADRs and the one hundred and eleven rules were applied on 2026-11-09 and 2026-11-10 to the ADRs, the command map, the compiler and the roadmap, and all six open design items are drafted (queue schemas and artifact scrub as ADR 0012 decision 10 and ADR 0007 amendment 5, and the inner loop from a developer's laptop as [ADR 0022](adr/0022-the-laptop-lends-a-tree-the-cluster-builds-it.md): the laptop lends its working tree as snapshots, the cluster builds and runs it as a dev unit, and the editor's debugger reaches it through `attach -L`). [ADR 0013](adr/0013-native-verbs-have-one-shape.md) drafts the native verbs (`explain`, `run`, `batch`, `wait`, `replay`, the unit, device and platform verbs) as a closed set with one seven-field shape, so the stories have a text to be checked against, [ADR 0015](adr/0015-tables-and-catalogs-are-devices.md) drafts tables and catalogs (Iceberg, Delta, Hudi, warehouses) as the `/dev/table` class, where a read pins a snapshot and a write is one commit, and [ADR 0014](adr/0014-assisted-completion-the-model-proposes.md) drafts assisted completion: type-directed from the grammar first, a model only ranking and translating, and the model itself a device. [ADR 0021](adr/0021-a-node-is-tested-before-it-is-trusted.md) drafts node health without a person present: probes test each component, a policy acts on clear faults, a health agent judges the ambiguous ones within a fixed set of actions and a disruption budget, and a GPU or a shared-filesystem client is excluded before its node. [ADR 0023](adr/0023-telemetry-is-a-device-the-shell-reads.md) drafts telemetry as devices: metrics, logs and traces read from the platform's own stores by bounded, priced selector reads, with absence reported as `unknown`, so the shell reads the monitoring system and never becomes one. [ADR 0024](adr/0024-a-device-is-installed-by-terraform.md) makes Terraform the install phase of every device: a device package carries a contract and a module per provider, `mknod` plans and installs through the platform's runner, and a device moves between providers as a new instance of the same contract. [ADR 0025](adr/0025-a-computer-is-a-device-kubernetes-is-one-driver.md) makes compute a device class with Kubernetes as one kind beside Slurm, functions, batch services and VM pools, each with a driver that fills one contract, so one pipeline is placed across them and across regions by the same ordered filter. [ADR 0026](adr/0026-a-registry-is-a-device-a-tag-is-a-name-for-a-digest.md) makes OCI registries devices: tags are names for digests resolved once at plan time, signatures and SBOMs are files beside their digest, promotion is a copy with them, and nothing in use can be deleted or expired. [ADR 0027](adr/0027-convoy-tells-a-group-about-its-own-objects.md) gives Convoy's own events (approval requests, failures, expiries, disconnections, health actions) a route per group to the chat, mail and incident channels the platform already runs, with urgency, roll-up per process tree and no output in the message. [ADR 0028](adr/0028-memory-has-a-distance-and-a-domain-is-claimed-whole.md) gives memory a distance: every computer reports its tiers and its domains (an NVLink rack, the NUMA nodes of a host), a gang claims one domain whole, shared in-memory stores are volatile devices under `/dev/shm/`, and nothing is shared across computers. [ADR 0029](adr/0029-a-computers-file-systems-are-in-its-contract-staging-is-a-planned-copy.md) puts each computer's file systems in its contract and makes staging a planned, priced, verified copy: inputs are read in place where the computer can reach them and staged where it cannot, and what staging creates ends with the process. [ADR 0030](adr/0030-an-interactive-process-holds-a-computer-while-someone-is-attached.md) gives interactive work its own process class: a terminal or a notebook that holds a computer while someone is attached, reached through the gateway, ended when idle or abandoned with a warning, and marked in the lineage of what it writes. [ADR 0031](adr/0031-an-edge-computer-is-reached-by-contact-and-known-by-what-it-delivers.md) makes devices with no API (vessels, camera boxes, buoys) computers of kind `edge` that pull their work at contact, with contact in the contract, delivery states for work whose only copy is on the device, and identities that last a voyage.
